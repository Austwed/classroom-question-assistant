# 通用语音问答助手

## 目标与状态

状态：进行中。这个 Windows 原型监听一个电脑播放设备的系统声音，识别普通话内容，再交给本机 llama.cpp、OpenAI GPT 或兼容 API 回答。也可直接输入文字提问。用户可建立包含身份、背景和说话方式等字段的人设，不预设学科或课堂角色。

程序默认只在自己的窗口显示文字，不自动向其他软件发送消息，也不播放语音。用户主动开启“手机共享”后，可在同一局域网的手机浏览器中只读查看本次运行的回答。

## 功能

- 列出播放设备，选择扬声器或耳机，并以 WASAPI Loopback 采集该设备正在播放的声音。
- 显示实时音量、语音转写和回答。每段有效发言先进入转写队列，再进入回答队列；回答较慢时，后续语音仍可继续转写。每段转写都会单独尝试回答，不等待下一段拼成完整问题。
- 本次打开软件后的语音与手动提问共用一份内存中的完整对话历史；每次回答都带上此前真实发言及已生成的回答，不按监听会话分割，也不人为裁剪轮数。关闭并重新打开软件会开始一份新记忆。修正转写后，后续回答使用修正版；问“之前问过什么”时以真实发言记录为准，不把人设或预置答案当作发生过的对话。
- 问答页逐段显示片段编号、来源、监听会话、人设、模型、处理状态、转写预览和阶段耗时。两个队列各容纳 6 段；满载时会留下“未入队”记录和原因。
- 逐段进度采用两行显示；处理进度与识别记录均可独立折叠，识别记录与回答可拖动分隔线调整高度。回答可最大化，占据问答页顶部控件以下的区域，退出后恢复折叠状态。设置页分为“人设”“回答模型与密钥”“语音与显示”三页，保存按钮和未保存提示固定可见。布局与配置行为见 [界面与配置改进记录](docs/interface-settings-design.md)。
- 转写队列满时最多在内存中暂存 3 段音频，总量上限 12 MB；选中片段可重试。超出上限时会淘汰最早暂存的音频，并在对应片段中标明。回答队列满时保留转写，可选中重试。重试沿用该片段原来的人设和模型，快速连点不会重复入队。
- 点击“停止监听”只停止收音；已录入的有效尾段和队列中已有片段继续处理。界面会显示剩余处理段数，直到全部完成。监听过程中保存的参数从下一次监听生效；手动提问使用当前界面参数。
- 启动后立即在后台加载选定的本地语音识别模型。主页显示加载状态，加载完成后“开始监听”可用；不必等到第一段语音才加载。切换识别方案后会重新预加载。
- 默认用本地 FunASR Paraformer 中文模型识别，支持专有词热词；可在“设置 → 语音与显示”切换到 Whisper `base`。所有转写文字均转换为简体中文。
- “设置”中分别填写身份、场景与对象、背景事实、知识范围、说话方式、常见问题要点及其他场景指令，还可设置语音识别方案、播放设备、回答模型、声音阈值、发言结束前的静音时间、字体大小和奇偶回答颜色。固定通用规则与可切换场景的设计见 [人设分层设计](docs/persona-architecture.md)。参数保存在本机 `config/app_parameters.json`；API Key 默认另存于当前 Windows 用户的凭据库。旧 `config/teacher_settings.json` 保留原文件，但程序不再读取。
- 设置页会提示哪些改动尚未保存；切到 Whisper 时热词输入会禁用但内容保留。保存时检查当前模型服务的地址格式，非当前服务的字段可暂时留空。云端 Key 可临时显示或隐藏，保存状态与环境变量状态分开提示。
- 可把当前完整场景字段保存为多个人设，再从列表中选择并应用；人设保存在本机 `config/personas.json`。旧人设会保留身份与补充指令，新字段默认为空。同名保存会先询问是否覆盖。应用后手动提问立即使用；正在监听的语音从下一次监听起使用。
- 回答栏按生成顺序编号，显示片段编号与必要的修正标记，不重复显示人设和模型；第 1、3、5 条回答使用奇数颜色，第 2、4、6 条使用偶数颜色。颜色只影响显示，不影响复制或导出的纯文本。
- 问答页可手动开启手机共享，选择电脑的局域网地址并扫码打开只读网页。手机先加载本次运行已生成的回答，再实时接收新回答；断线重连后按编号补齐遗漏回答。手机页可用“A− / A＋ / 默认”调整内容字号，并收起“本次运行的回答”标题区；同一手机页面刷新后保留这两项显示偏好。纠正回答会在手机上标记旧回答已被替代。关闭共享或退出程序后，临时链接失效。
- 默认通过 `http://127.0.0.1:8080/v1/models` 找到本地模型，再调用 `/v1/chat/completions` 生成回答。GPT 模式使用 Responses API，默认模型为 `gpt-6-sol`（低推理强度），模型名可修改。每段发言仅需一次模型调用。
- “兼容 API”支持使用 Chat Completions 格式的服务，包括 DeepSeek。可用“填入 DeepSeek 预设”设置官方地址和 `deepseek-flash` 模型；其他服务填写其 API 基础地址和准确模型名。DeepSeek 预设关闭思考模式，以缩短实时问答等待并确保回答显示；其他兼容服务不发送 DeepSeek 专用参数。
- 可以在不监听声音的情况下手动输入一句话。转写有误时，可点“载入最近转写”，或双击进度中的指定条目，修改文字后重新生成回答。修正版关联原片段并沿用其人设和模型；修正回答成功后，原回答标为“已被修正替代”。
- 识别记录和回答均可选中文字按 Ctrl+C；未选中文字时按 Ctrl+C 会复制该框全部内容。两个框也各有复制按钮。
- “导出对话记录”按片段编号导出本次运行的转写、回答、失败或未入队状态、会话、人设、模型和修订关系；原回答与最终修正版可区分。文件采用 UTF-8 编码。
- 本地 llama.cpp 模式会关闭模型的额外思考输出；若正式回答仍为空，会自动重试一次。

## 运行平台与依赖

- Windows 10/11，Python 3.12。
- 本地模式需要正在运行的 llama.cpp 服务，默认地址 `http://127.0.0.1:8080`，且已加载一个聊天模型；云端模式需要网络连接及对应服务商的 API Key。
- Python 包见 `requirements.txt`；语音模型文件保存在本项目 `models/`。二维码由 `qrcode` 包在本机生成。
- 初次执行 `setup.cmd` 需要联网下载依赖和语音模型，中文增强模型约需 2 GB 磁盘空间。语音识别始终在本机完成；云端模式每次回答会将当前转写、本次运行此前的有效发言与回答、固定通用规则及当前人设全部场景字段发送给所选 API 服务商，并由该服务商按 API 用量计费。ChatGPT 或 DeepSeek 网页订阅不等于 API 额度。

## 安装与启动

在本目录双击 `setup.cmd` 完成一次安装，然后双击 `start.cmd`。也可以在命令行执行：

```cmd
setup.cmd
start.cmd
```

如果电脑没有全局 Python，脚本会尝试使用 Codex 工作区附带的 Python。安装好的依赖留在本项目 `.venv/`，不写入系统 Python。

要使用 GPT，在“设置 → 回答模型与密钥”把“回答模型”改为“OpenAI GPT（云端）”，在密码框输入 API Key。点击“保存设置”，或直接开始监听／手动提问时，软件会自动把输入的 Key 保存到当前 Windows 用户的凭据库；之后重启软件可留空密码框直接使用。也可在启动程序前设置 `OPENAI_API_KEY` 环境变量。读取顺序为本次输入、Windows 凭据库、环境变量。密钥不写入项目设定、日志或导出包；如果凭据库不可用，界面会提示 Key 未保存，本次运行仍可使用已输入的 Key。每段识别出的发言调用一次 API。切换模型后，新提交的手动测试立即使用新模式；监听中的语音沿用点击“开始监听”时选定的模式，需停止后重新开始才能切换。

要使用 DeepSeek：

1. 从 [DeepSeek 官方平台](https://www.deepseek.com/platform/)申请 API Key，并确认 API 余额可用。
2. 在“设置 → 回答模型与密钥”把“回答模型”改为“兼容 API（DeepSeek 等）”，点击“填入 DeepSeek 预设”。界面将填入 `https://api.deepseek.com` 和 `deepseek-flash`。如需 V4 Pro，可把模型名改为 `deepseek-v4-pro`。
3. 在 API Key 密码框输入 DeepSeek Key，或在启动软件前设置 `DEEPSEEK_API_KEY` 环境变量；点击“保存设置”，回到“问答”页先用手动提问测试。直接在软件输入的 Key 会保存在 Windows 凭据库，不写入参数文件。

接入其他**支持 OpenAI Chat Completions 格式**的 API 时，同样选“兼容 API”，填写服务商文档给出的 API 基础地址（不要附加 `/chat/completions`）、模型 ID 和对应 Key。也可在启动前设置 `COMPATIBLE_API_KEY`。不同 API 基础地址的 Key 分开保存；切换地址不会沿用原服务的 Key。远程地址必须使用 HTTPS；本机服务允许 HTTP。某些服务只支持 Responses API 或采用专有协议，需要单独适配。

“清除已保存 Key”只删除当前模型服务对应的 Windows 凭据；它不更改环境变量。凭据按当前 Windows 用户保存在这台电脑，复制源码包到其他电脑不会带走 Key。凭据库接口采用 Windows 的 [通用凭据](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw)；同一 Windows 用户下运行的程序仍可能访问该用户的凭据，因此不要在共享账号中保存私人 Key。

## 基本验证

1. 使用本地模式时，打开 llama.cpp 服务，确认 `http://127.0.0.1:8080/health` 返回 `ok`。使用云端模式时，填入对应 API Key 并确保网络可用。
2. 启动后观察“正在加载语音识别模型…”提示；加载完成后“开始监听”按钮变为可用。首次启动时加载可能需要十几秒，但可同时操作界面或先进行手动文字问答。
3. 在“设置 → 人设”填写身份、场景和背景；在“回答模型与密钥”“语音与显示”分别设置模型、设备、阈值、停顿、字体和颜色，点击底部“保存设置”。可以点击“保存当前为人设”命名保存，之后从列表选中并点击“应用选中人设”切换。
4. 返回“问答”页，手动输入“请说说三角形和圆的区别”，点击“生成回答”；再输入另一句话，确认第 1、2 条回答分别采用奇数和偶数颜色。
5. 点击“开始监听”。播放一段中文发言，确认音量数字变化；声音停顿达到设置时长后，检查逐段进度、识别记录和回答。如果音量变化但一直没有转写，可将阈值从 `0.008` 调到 `0.003`，停止后重新开始监听。
6. 连续播放两段发言，并在第二段入队后点击“停止监听”：确认状态先显示仍有片段处理中，随后显示全部处理完成，且两段都有对应结果或明确错误。
7. 折叠处理进度和识别记录，确认回答区域变高；点击“最大化回答”，确认回答占据手动提问框以下的空间，点击“还原回答”后折叠状态保留。选中记录或回答文字按 Ctrl+C 测试复制；不选中文字时可复制整框。点击“导出对话记录”，核对保存的文本包含发言与回答。
8. 若转写有误，双击该片段并编辑后生成修正回答，检查原片段状态变为“已被修正替代”；导出记录应同时标明原答和修正版。队列满时选中“未入队”片段点击“重试选中片段”。
9. 在同一次打开软件期间，先用语音询问动态批处理，再手动询问 SRP Batcher，最后问“我问你的第一个问题是什么”；确认回答依据第一段实际发言。关闭并重新打开软件后再问同一句，确认不会沿用上次记忆。
10. 电脑和手机连接同一 Wi-Fi，在问答页点击“开启手机共享”。如有多个 IP 地址，在弹出的窗口里选择手机可访问的那个地址，再用手机扫描二维码。先在电脑生成一条手动回答，确认手机页面出现；在手机页用“A− / A＋”调整字号，收起并重新展开标题区。让手机断开网络后再生成一条，恢复网络并重新打开页面，确认遗漏的回答补齐。点击“停止手机共享”，确认原链接不再可用。

自动化回归检查：

```cmd
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## 输入、输出及导出

- 输入：所选 Windows 播放设备的声音，或手动输入的文字。
- 输出：本程序窗口中的识别记录和回答；主动开启手机共享时，手机浏览器可只读查看本次运行的提问与回答。
- 原始录音不保存到文件。对话记忆只在本次运行的内存中，对话记录只在用户点击“导出对话记录”后写入所选文件；关闭窗口后未导出的历史内容消失。自定义参数和多个人设保存在本机。云端模式会发送当前转写、此前有效发言与回答、固定通用规则和当前人设的全部场景字段到所选 API 服务商；原始音频不发送。
- 本地 llama.cpp 地址只接受本机 HTTP 地址（`127.0.0.1`、`localhost`、`::1`）。兼容 API 地址接受 HTTPS；HTTP 仅限本机。云端 API Key 保存在当前 Windows 用户凭据库，不存入 JSON 文件。
- 最新可分享源代码包是 `08_Exports/classroom-question-assistant/通用语音问答助手-手机同步与字号版.zip`。运行时依赖和语音模型须在目标电脑安装。

## 已知限制

- 系统声音回录只覆盖所选**一个播放设备**，不包含未播放出来的本机麦克风声音。多设备同时收音留待后续版本。
- 混合声音无法可靠识别说话者；视频或网页中的人声也可能触发。请按需手动开启监听。
- 中文增强模型仍可能在噪声、多人重叠和生僻术语下出错；音量阈值也需按设备调节。术语热词用逗号隔开，可改善特定词汇识别，但不能保证每次正确。
- 中文增强模型加载或推理失败时，识别记录会显示原因，随后自动改用 Whisper `base` 处理该段声音。
- 语音识别暂用 CPU，避免与 27B 本地模型竞争显存；实际延迟取决于电脑和声音长度。
- 每段成功进入回答队列的发言都会调用回答模型，普通陈述、背景视频中的人声和误转写也可能产生回答及 API 费用；使用者应核对生成内容。
- 音频重试缓存仅在内存中，最多 3 段、12 MB；较早的缓存可能因容量限制被淘汰。程序关闭时清空缓存，音频不会写入导出文件。没有音频或转写的片段无法重试。
- 云端模式依赖所选服务商的可用性、模型访问权限和 API 余额；网络超时或额度不足会在识别记录中显示错误。当前没有离线自动回退，出错时可手动切回本地模式。
- 对话记忆不设软件层面的轮数上限；若一次运行积累的文本超过所选模型的实际上下文窗口，服务会返回错误，程序不会静默删除较早的发言。真实模型仍可能给出错误答案，应核对重要事实；本次改动确保它能看到真实对话记录，并要求它在记忆不足时坦诚说明。
- 手机共享只支持同一局域网，电脑必须保持开机且软件运行；手机锁屏时浏览器可能暂停实时连接，重新打开后会补齐。Windows 防火墙第一次可能询问是否允许此程序访问专用网络，应只在可信的专用网络中允许。网页使用局域网 HTTP，传输本身未加密；请勿在公共 Wi-Fi 上共享敏感回答，也不要把包含临时访问凭据的二维码或链接转发给他人。手机网页不会收到 API Key、音频、人设配置或模型设置。
- 如果电脑有多个网络适配器，开启手机共享时会提示选择一个 IPv4 地址；请选择手机所在网络能访问的地址。手机若无法打开，可检查是否处于同一 Wi-Fi、路由器是否开启客户端隔离以及 Windows 防火墙的专用网络权限。
- 若仍遇到语音回答错误，可以点击“复制最近转写”获取该段识别文字，再用主页的手动输入重试。同一段文字也失败时，记录中会显示更具体的本地模型结束原因。
