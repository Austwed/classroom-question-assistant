# 语音识别与响应流程设计

状态：逐段状态、双队列、按条修正、有限重试缓存和本次运行对话记忆已实现；真实设备基线测试待完成。适用范围：Windows 单个播放设备的系统声音回录，回答只显示在本软件窗口。

## 本轮目标

在保留“每段识别出的有效发言都尝试回答”的前提下，让使用者看清一段声音从录入到回答的状态，减少因切段和排队造成的重复、漏答与过时回答，并能方便地修正转写。身份、人设以及本地、OpenAI、兼容 API 三种回答方式继续沿用现有设置。

## 现状与依据

当前 `audio_capture.py` 每 200 毫秒取一帧，以音量阈值判断发言开始，以可配置的静音时间判断结束；最多录制 60 秒。点击停止后，已录入且达到有效发言长度的尾段也会提交。`app.py` 将转写和回答分为两个各容纳 6 项的队列，分别由一个后台线程处理。回答变慢时，后续语音仍可先转写；队列满时为片段留下可见的“未入队”状态。转写队列满时最多在内存暂存 3 段、12 MB 音频；回答队列满时保留转写。转写失败可回退到 Whisper；用户可以选中片段重试或纠正转写。

当前界面显示片段编号、来源、监听会话、身份、回答模型、识别方案、处理状态，以及转写和回答各自的等待与处理耗时。预加载状态与待处理数量分开显示。真实使用中的误触发率、识别准确率和各阶段耗时尚无基线数据，因此切段参数变化仍应由试用数据决定。

## 处理流程与后续设计

```text
播放设备回录
  → 音量检测与切段
  → 为语音片段分配编号、时间和监听会话编号
  → 转写队列 → 本地语音识别 → 显示并允许修正转写
  → 回答队列 → 所选模型生成文字 → 显示回答
```

1. **逐段状态（已实现）。**界面按编号显示“等待转写、正在转写、等待回答、正在回答、已完成、失败、未识别或未入队”。同一行包含转写预览、错误和耗时；手动文字提问也生成记录，来源标记为“手动”。
2. **两阶段队列（已实现）。**回录线程只负责切段与入队；语音识别和回答各有独立的串行工作队列。新发言无需等前一条云端回答结束才开始转写。
3. **满载与重试（已实现）。**两个队列都有 6 项上限。满载时界面留下“未入队”记录及原因。音频只在内存中暂存，最多 3 段、12 MB；超限淘汰最早缓存并标明“音频未保留”。回答队列满时保留转写。点击重试沿用原片段的设置，成功入队后再点不会重复提交；关闭程序清空音频缓存。
4. **转写纠正（已实现）。**双击进度行可载入该段转写，修改后新建关联原片段的“修正”记录，并沿用原身份与回答模型。修正回答成功才把旧回答标记为“已被修正替代”；失败时旧回答仍保留。连续修正形成编号链。自动转写仍默认进入回答。
5. **会话与方案溯源（已实现）。**每次开始监听创建新的会话编号。监听过程中保存参数不会改变当前会话的身份、识别方案和回答模型；新设置从下一次监听或下一条手动提问生效。旧会话异步结果仍更新所属记录。进度和导出标明身份与模型，语音片段另标识别方案；回答栏只显示片段编号与必要的修正标记。
6. **等待和处理耗时（已实现）。**界面显示转写、回答各自的等待和处理秒数；错误信息指出出错阶段，不显示调试栈或密钥。若要导出完整性能日志，后续再补充原始阶段时间戳。
7. **停止监听只停止收音（已实现）。**点击“停止监听”后，已录入的有效尾段与已成功入队的片段继续转写、回答，直到队列清空。界面区分“已停止收音，仍有 N 条处理中”和“全部处理完成”。
8. **本次运行对话记忆（已实现）。**每段转写仍立即调用回答模型，不等待其他片段。语音与手动提问按片段编号共用同一份内存记忆，即使停止再开始监听也会延续；关闭程序则清空。每次请求都按顺序发送此前有效发言、已生成的回答和当前片段。修正链在后续请求中只保留最新转写，避免旧的错误转写混入记忆。回答过去的提问时，真实用户发言优先于人设背景或模型此前的猜测。OpenAI Responses API 使用 `input` 消息数组，本地和兼容服务使用 `messages` 数组。

## 切段与识别策略

第一步保留现有音量阈值、前置缓存和静音时间，先用真实语音做基线记录。测试样本至少覆盖短问句、长陈述、句中停顿、多人轮流说话、背景视频和安静时的系统提示音。每段记录是否被切断、是否与下一句合并、转写是否正确，以及从发言结束到回答出现的时间。

若主要问题是把句中停顿切断，可调高静音时间；被拆出的每段仍独立回答，并通过完整对话记忆理解上下文。后续可考虑手动合并相邻片段，但不以等待合并为回答前提。若主要问题是噪音触发，再评估将语音活动检测加入切段；仅提高固定音量阈值可能同时漏掉轻声发言。语音活动检测只能判断是否像人声，不能保证说话者身份或内容相关性。

## 当前界面示意

```text
监听中：耳机 · 本次 1 段处理中
语音识别：funasr 已就绪

逐段处理进度（双击条目载入转写）
#18  会话 2 · 语音 · 正在回答 · 求职者 / 本地模型 · 请说说 A 和 B 的区别
#17  会话 2 · 语音 · 已完成 · 求职者 / 本地模型 · 识别 1.5s / 回答 4.2s
[重试选中片段（沿用原人设与模型）]

回答区：第 17 条 · 片段 #17
```

当前的奇偶颜色继续作用于已完成回答；状态、错误和转写使用独立的中性样式。导出按片段编号保留原答与修正版、失败和未入队状态，并标明最终采用的回答；不导出原始音频或密钥。导出时仍在处理的片段会标明当时状态。

## 实施顺序与验收

1. 已完成：片段编号、状态、阶段耗时和停止后继续处理；自动化测试覆盖有效尾段、两阶段并行和会话设置固定。
2. 已完成：转写与回答拆成两个串行队列，满载时显示“未入队”。仍需在真实设备上验证持续语音负载。
3. 已完成：按条修正、有限缓存、原设置重试和带修订关系的导出。自动化测试覆盖连续修正、缓存淘汰、快速连点、会话设置固定及预加载与待处理状态并存。
4. 已完成：统一语音和手动提问的本次运行记忆；自动化测试检查三问后回溯第一题、修正版替换旧转写以及三种模型接口的历史消息格式。
5. 用用户设备上的真实网课音频测基线，再决定是否调节切段默认值或增加语音活动检测。对比修改前后的漏段、误段和发言结束到回答出现的时间。

## 边界

单设备系统回录会包含该设备播放的全部声音；当前没有可靠的说话者识别。云端回答仍只发送转写文字、人设与回答要求，原始音频不发送。任何云端请求及费用都取决于使用者主动选择的服务和该服务的账户配置。
